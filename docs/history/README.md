# История крупных коммитов и фич

Здесь лежат пояснения к значимым изменениям в проекте — не построчный changelog,
а контекст: зачем это сделано, какие альтернативы рассматривались, на что обратить
внимание при следующих изменениях в этой области.

Заводить запись стоит для: архитектурных решений, крупных рефакторингов, новых
фич с нетривиальной логикой. Не стоит — для опечаток, мелких правок стилей,
рутинных обновлений зависимостей.

## Формат

Один файл на запись: `YYYY-MM-DD-краткий-слаг.md`.

```markdown
# Заголовок

**Дата:** YYYY-MM-DD
**Коммит(ы):** <hash или диапазон, если уже закоммичено>

## Зачем

Что было до и почему потребовалось изменение.

## Что сделано

Кратко, по сути — не пересказ диффа, а ключевые решения.

## Почему так, а не иначе

Рассмотренные альтернативы и причина выбора текущего подхода.

## На что обратить внимание

Нюансы, которые не очевидны из кода, но важны при следующих изменениях.
```
